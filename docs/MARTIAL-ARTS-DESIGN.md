# 武学系统设计：心法 · 招式 · 真气（傀儡版）

> 版本 v1 / 2026-11-01。本文是**立项依据 + 机制拆解 + 数值定稿**，本轮**只出文档**，不动代码。
> 对标对象是《逸剑风云决》（下称「逸剑」）的招式/心法，横向参考《太吾绘卷》《侠客风云传》《河洛群侠传》。
> 读法：§1 是别人的东西，§2 是我们自己的地基，§3 之后才是设计。

**结论先行：**

1. 逸剑的「繁多」**不是招式数量堆出来的**，而是四个乘区叠出来的：**资源（真气）× 档位（二式/三式/绝式）× 克制（破招/内伤/断筋）× 成长（心法境界/修为）**。要抄就抄这四层，不要抄它的战棋棋盘。
2. 傀儡版落成三层：**心法（1 门，管资源与成长）→ 招式（按档位各 1 个，管出手节奏）→ 绝学（现有 5 个特技，本轮不动）**。
3. 只新增一条资源「**真气**」，它只做三件事：**攒、花、卡阈值**。不做集气条、不做侧背击、不做内外功比例 —— 这三样是玩家操作层的，自动战斗单位拿不到收益（§1.6 有逐条判定）。
4. 招式**不另起一套结算**，而是走 `GolemMeleeHelper.normalAttack` 的「普攻管线」（附魔/磨砺/炎拳/莫厄照常触发）；破绽的追加伤害单独走一个伤害类型 `move_break`，避免和现有乘区双重叠乘。
5. 内容量：**心法 8 门、招式 18 个**（剑/刀/拳掌/棍/暗器 × 二式/三式/绝式），分 P0–P5 落地（§10）。

**本文不做：**

- 不做玩家侧心法/招式（这套是「装到傀儡身上的升级件」，玩家侧已有神通棍/架势那条线，不混）。
- 不做轻功类招式（傀儡的移动技已有冲撞/凤凰，P5 再议）。
- 不改现有 5 个特技的触发与数值（用户明确定调：这一轮先不碰，只把它们定义为「绝学」层的占位）。
- 不引入战棋、集气条、内外功比例、正逆练、参悟突破这类局外养成。

**术语（本文用法）**

| 词 | 含义 |
|---|---|
| 真气 | 新资源，招式消耗它；有上限、回复、三个阈值 |
| 心法 | 1 门，决定真气上限/回复/阈值/相性；L1–L3 = 境界 |
| 招式 | 耗气的主动技，按档位（二式/三式/绝式）各装 1 个 |
| 绝学 | 现有 5 个特技的统一称呼，本轮不动 |
| 破绽 | 敌人身上的叠层，招式命中时追加独立伤害，绝式吃掉 |
| 硬直 | 出招后短暂拉长攻击间隔 |
| 调息 | 无目标 3 秒后的快速回气状态 |
| 走火入魔 | 血魔专属：气不足也能出招，代价是扣血 + 内伤 |

## 1. 参考：四部游戏的武学拆解

可信度标记：**✅** = 解包数据/官方文本；**◐** = 二手攻略/评测；**？** = 存疑未证。

### 1.1 逸剑风云决（主对标）

| 机制 | 事实 | 可信度 | 对傀儡的用处 |
|---|---|---|---|
| 招式分类 | 按兵器分五类：**剑、刀、拳掌、棍（枪）、暗器**；指法/腿法并入拳掌，**没有**奇门 | ✅ | 直接照搬五类，决定「装什么招式看手里什么武器」 |
| 招式档位 | 每招带档位：**普攻（0 真气、无 CD）/ 二式 / 三式 / 绝式（长 CD 大招）** | ✅ | 这是整套系统的骨架：档位 = 资源消耗 × 冷却 × 硬直 的三级台阶 |
| 技能栏 | 界面 6 个栏（普攻/二式/三式/绝式/轻功/心法），每栏配 4 个备选、战斗中可切；心法最多同时装 4 门 | ◐ | 傀儡不能中途切招，所以「一档一招」比「一档四备选」更合适（§3.3） |
| 真气 | 招式资源，普攻免费；部分心法「用招不耗气」甚至回气 | ✅ | 真气 = 我们唯一的新资源；「某些心法让某类招式免费」是很好的心法差异点 |
| 调息 | 一个专门动作：回气血/真气，清封步，削破招/内伤/断筋层数；受「调息效果」词条影响 | ✅ | 傀儡的「无目标待机」天然就是调息窗口，不需要新 AI |
| 集气条 | 半即时战棋的行动序，大量效果直接改写集气（+100%、气绝清零） | ✅ | **不搬**：傀儡的行动序就是攻击间隔，再叠一条集气只会打架 |
| 连击/连行 | 「连击」状态只能重复上次招式或调息；「连行」可移动/调息但不能出招 | ✅ | 可改造为「同招递减 + 收招硬直」（§6.4/§6.6） |
| 心法 | 主动（BUFF/伤害/位移）+ 被动（属性、真气% 条件效果、门派/兵器类招式增伤）+ **4/5/7/10 级里程碑**；每级给经脉点 + 气血/真气上限 | ✅ | 「真气% 阈值开关」和「按兵器类加伤」原样可搬；里程碑改成本仓库的「境界 + 修为」 |
| 克制 | 不是属性石头剪刀布，而是**禁动作类别**：破招（不能出招，每层防御 −10%）、内伤（不能用心法）、断筋（不能移动/轻功）、气绝（清空集气）、封穴（破招+断筋+减速） | ✅ | 原版怪没有「招式」概念，这五个只能对**傀儡/玩家**生效 → 本轮只做接口，主力改成敌人侧的「破绽」（§7） |
| 侧背击 | 侧击/背击加成，绕后是主要空间博弈 | ✅ | **不搬**：傀儡不绕后，AI 没这个决策 |
| 自动战斗 | 自带即时/回合 × 自动/手动四种模式，自动模式能跑完整套循环 | ◐ | 这是「心法+招式对自动单位成立」的最直接证据 |

**它真正在做什么**（这段是设计的出发点，不是复述）：

- 心法 = **资源曲线 + 开关**：真气上限、真气% 阈值触发的攻/守模式、按兵器类给某类招式加伤。
- 招式 = **出手节奏**：真气消耗 × CD × 集气（行动序）。
- 克制 = **禁动作类别**：不是数值表，是「让你这一回合不能做某类事」，所以可读、可预判、可被 AI 兜底（敌人被断筋+破招时会转去调息）。
- 成长 = **两段**：心法等级/经脉点（局外，决定上限）+ 熟练度/实战发挥（局内，越用越强）。

### 1.2 太吾绘卷

| 机制 | 事实 | 可信度 | 对傀儡的用处 |
|---|---|---|---|
| 功法分类 | 14 类：内功、身法、绝技（护体/奇窍）+ 11 类「摧破」（拳掌/指法/腿法/暗器/剑法/刀法/长兵/奇门/软兵/御射/乐器） | ✅ | 验证「按兵器分家」是对的；我们的五类够用，不必拆 11 类 |
| 内功=资源 | 提供内力、运功栏位、周天运转、被动；最高造诣决定周天能放几门辅助内功 | ✅ | 「副心法」的原始出处（P5 可选，§12 问题 7） |
| 招式=节奏 | 耗提气/架势/蓄式；「内外功比例」决定提气/架势配比与内外伤比例 | ✅ | 内外功比例是玩家微调，**不搬** |
| 相克 | 功法六属性（金刚/玄阴/紫霞/纯阳/归元/混元），与本命内力冲克会反噬 + 内息紊乱；旧版数值 ±30%、混元 +10% | ✅/◐ | 可做成 P5 的数据包「相性表」（§7.4），默认关 |
| 养成 | 研读→参悟正/逆练→突破；「实战发挥」（熟练度）靠战斗使用提升 | ✅ | 「实战发挥」→ 我们的「修为/精修」（§5.4/§8.1） |
| 部位 | 施展依赖身体部位，部位重伤→施展时间翻倍，封穴 3 层→不可施展 | ✅ | **不搬**：傀儡没有部位系统 |

### 1.3 侠客风云传

| 机制 | 事实 | 可信度 | 对傀儡的用处 |
|---|---|---|---|
| 套路 | 一套「套路」= 3 招，各有 CD 与内力消耗，一技能 0CD；**切套路 → 全部进 CD** | ◐ | 「切套路全 CD」= 换招有代价；我们改成「同招递减」（§6.4），更轻 |

### 1.4 河洛群侠传

| 机制 | 事实 | 可信度 | 对傀儡的用处 |
|---|---|---|---|
| 六感悟 | 刚/柔/动/静/巧/拙，相生相克，并**按流派改写行为**：刚系独占暴击、柔系独占卸劲、动系越移动越强、**静系在射程内自动迎击**（不耗 AP 但耗内力）、巧系靠多学招式、**拙系同一招越用越强** | ✅/◐ | 「静系迎击」= 无需 AI 判断的被动反击；「拙系同招越用越强」= 精修/修为的现成说法 |
| 定位 | 六感悟是「流派 = 行为改写」，不是纯数值 | ✅ | 我们的「气性」（刚/柔/疾/拙）照这个思路做，每个气性改一条 AI 规则而不是只加数字 |

### 1.5 横向对比：谁管什么

| 层 | 逸剑 | 太吾 | 侠客 | 河洛 | 傀儡版落点 |
|---|---|---|---|---|---|
| 资源 | 真气 | 内力 + 提气/架势/蓄式 | 内力 | AP + 内力 | **真气**（一条，够用） |
| 节奏 | 真气/CD/集气 | 内外功比例/部位 | CD/切套路 | 移动/射程 | **CD + 收招硬直** |

| 成长 | 心法等级/经脉 | 正逆练/突破 | 招式等级 | 多学招式/同招熟练 | **境界（物品等级）+ 修为（使用量）** |

### 1.6 移植判定：能搬 / 不能搬 / 改造后能搬

| 机制 | 判定 | 理由 |
|---|---|---|
| 真气条 + 阈值开关（≥X% 攻 / <X% 守） | ✅ 直接搬 | 傀儡 AI 读一个数就能决策，不需要预判 |
| CD 大招 + 无耗普攻填充 | ✅ 直接搬 | 决策空间小、可预期，正是自动战斗需要的 |
| 「调息」兜底动作 | ✅ 改造 | 傀儡的「无目标」就是调息，不必新增动作 |
| 击杀再动但递增消耗 | ✅ 改造 | 傀儡没有「再动」，改成击杀回气 + 连杀递减（P5） |
| 被动反击/迎击（太极、静系） | ✅ 直接搬 | 不需要 AI 主动判断，受击事件里结算 |
| 心法按兵器/门派给软加成 | ✅ 直接搬 | AI 只需匹配标签，不需要理解 |
| 禁招类控制（破招/内伤/断筋/气绝/封穴） | ◐ 只做接口 | 原版怪没有「招式/心法/轻功」，五类里只有「减速/清资源」通用；对傀儡/玩家 PvP 才完整 |
| 集气/行动序条 | ❌ 不搬 | 与攻击间隔重复，且会让「硬直」失去意义 |
| 侧背击/朝向/位移落点 | ❌ 不搬 | 傀儡不绕后，没有空间博弈 |
| 内外功比例、正逆练、参悟突破 | ❌ 不搬 | 局外微调/长线抉择，傀儡没有 build 界面 |
| 战斗中切套路/换心法 | ❌ 不搬 | 需要玩家实时输入；傀儡的「切换」只能是拆装升级件 |
| 部位重伤/封穴 | ❌ 不搬 | 傀儡没有部位系统 |

## 2. 本仓库地基（能直接用的东西）

### 2.1 `GolemModifier` 可挂的钩子（`javap` 实测，2.7.3）

| 钩子 | 触发时机 | 本设计用途 |
|---|---|---|
| `onGolemSpawn(golem, level)` | 生成/读档后 | 初始化真气、挂心法被动 |
| `onAiStep(golem, level)` | 每 tick（两端都会调，本仓库惯例先判 `isClientSide`） | 真气回复、调息、阈值切换、冷却推进 |
| `onHurtTarget(golem, event, level)` | 傀儡打中目标（`LivingHurtEvent`） | **近战招式触发**、攒气、上破绽 |
| `onHurt(golem, event, level)` | 傀儡被打了 | 受击回气、玄阴被动 |
| `onKillTarget(golem, target, event, level)` | 傀儡击杀（`LivingDeathEvent`） | 击杀回气、归元回血、连杀计数 |
| `onAttackTarget(...)` / `onAttacked(...)` | 攻击前 / 被攻击前（`LivingAttackEvent`，可取消） | 太极拳的反击判定、破招（P5） |
| `onSetTarget(golem, mob, level)` | 换目标 | 清「同招递减」链、进入/退出战斗态 |
| `interact(player, golem, hand, level)` | 玩家右键傀儡 | **右键诊断**（显示真气/心法/招式/修为） |
| `modifySource(golem, CreateSourceEvent, level)` | 构造伤害源 | 给招式伤害开 l2 的 BYPASS 通道（P5） |
| `onRegisterGoals` / `onRegisterFlag` | 注册 AI 目标/旗标 | P5 若要做「守势自动后退」才用 |

> 结论：**不需要新 mixin 就能完成 P0–P4 的全部运行时逻辑**，唯一的 mixin 改动在「工作台装件校验」（§10.4）。

### 2.2 已经成型、可以直接借的四个件

| 现有件 | 位置 | 借什么 |
|---|---|---|
| 黑猴架势 | `GolemStanceModifier` + `PlayerStanceHandler` + `StanceHudOverlay` | 「槽 → 层 → 消耗 → 追加伤害」的完整闭环；**追加伤害延迟 1 tick + 独立伤害类型**的写法；粒子环表现 |
| 特技（互斥） | `SpecialMoveUpgradeItem` + `special_move_upgrades` tag + `GolemUpgradeHandlerMixin` | 「不占槽 + 同类互斥」的实现范式，心法/招式的槽位规则直接照抄结构，换 tag 即可 |
| 秘奥义熟练度 | `GolemPhoenixHandler`：`MYSTIC_UNLOCK_USES = 50`，用满 50 次解锁 | 「按使用次数成长」的先例；修为/精修的计数器照这个存 NBT |
| 三连击 | `GolemComboHandler` | 阶段调度（`LINK_TICKS`）、**攻速绝对值压制**（`TARGET_ATTACK_SPEED = 0.6`，间隔 = `ceil(20 / min(1, 攻速))`）、`invulnerableTime = 0` 的注意点 |

另外两个「制度性」的先例：

- `GolemUpgradeLevels.levelOf(golem, "modulargolems:damage_up")`：**只算升级件贡献的等级，不算材质**——心法境界必须走同一条路，否则材质白送境界。
- `ModAttributes.END_RESTITUTION` 的注释：**把多个来源统一收进一个属性，再在监听器里夹上限**——真气上限/招式增伤照这个做（§4.6）。

### 2.3 缺口（现状 → 目标）

| 缺口 | 现状 | 目标 |
|---|---|---|
| 资源 | 只有架势槽（攻击/移动/受击攒，近战一次性消耗） | 真气：上限、回复、消耗、阈值四件套；架势保留，改成真气的**来源之一** |
| 主动技 | 特技只有 5 个、互斥、无消耗 | 招式：18 个、按档位各 1 个、耗气 + CD + 硬直 |
| 心法 | 无 | 8 门，管上限/回复/阈值/相性 |
| 成长 | 特技无成长；秘奥义只有「50 次解锁」一档 | 心法境界（物品等级）+ 修为（使用量）+ 招式精修（单招使用量） |
| 敌人侧状态 | 磨砺（`GolemAttritionModifier`）在敌人身上存记录 | 破绽层数（通用、可叠、可被绝式吃掉） |
| 表现 | 架势有火焰环 | 真气环（颜色随阈值）+ 调息粒子 + 右键诊断 |

### 2.4 三条硬约束（写代码前必须知道）

1. **`UpgradeItem.get()` 没有 `ItemStack` 参数**，所以「一件物品代表一个招式」是硬性的：18 个招式 = 18 个 item id，不能靠 NBT 复用一件。
2. **`GolemUpgradeItemHandler.golem` 是 `ItemStack`**（傀儡物品），`GolemHolder.getUpgrades(stack)` 能读到已装升级 → mixin 里可以算心法境界，但 `GolemUpgradeLevels` 目前只接受实体，需要补一个 `Iterable<IUpgradeItem>` 重载。
3. **`maxLevel` 是 `final`、读不了配置**：任何「配置里能封顶」的等级都要在代码里再夹一次（`GolemCommandModifier.effectiveLevel` 踩过这个坑）。

## 3. 总体设计

### 3.1 三层 + 一条资源

```
                     ┌──────────────── 心法（1 门，L1–L3）────────────────┐
                     │ 真气上限 / 战斗回复 / 调息 / 守·攻阈值 / 兵器相性 / 修为 │
                     └───────────────────────┬────────────────────────────┘
                                             │ 境界解锁档位
   普攻（0 耗，攒气）──► 二式（低耗）──► 三式（中耗）──► 绝式（高耗，吃破绽）
        │                  │               │                │
        │              破绽 +1          破绽 +2         消耗全部破绽
        │                  └───────────────┴────────────────┘
        └── 命中/受击/击杀 → 真气 ──► 满 70% 进「攻势」，低于 30% 进「守势」
                                             │
                                    无目标 3 秒 → 调息（快速回气、清内伤）
```

三层职责：

| 层 | 装几个 | 管什么 | 玩家怎么获得 |
|---|---|---|---|
| **心法** | 1 门（同类互斥） | 资源曲线（上限/回复）、阈值开关、相性、成长上限 | 玉简合成；同件装 3 份 = 境界 L3 |
| **招式** | 每档 1 个（二式/三式/绝式各一） | 出手节奏（耗气 × CD × 硬直）、破绽施加/消耗 | 残页合成；档位受心法境界限制 |
| **绝学** | 现有 5 个特技，1 个（互斥） | 大招式、不耗气、长 CD | 本轮不动 |

### 3.2 核心循环（设计意图）

一场战斗里傀儡应该表现成这样：

1. **前 3~5 秒**：普攻攒气，二式起手，给目标上 1~2 层破绽。
2. **5~15 秒**：气过 70% 进「攻势」，三式扩伤，破绽叠到 3~5 层。
3. **15 秒左右**：绝式收割，吃掉全部破绽，打完进硬直（攻速短暂下降）。
4. **脱战**：3 秒后调息，7 秒左右回满，清掉内伤。

这条循环的每一段都能被玩家看懂（真气条/破绽层/硬直），但不需要玩家操作 —— 这正是逸剑自动模式能跑通的原因，也是这套系统对傀儡成立的根据。

### 3.3 关键取舍

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| 心法几门 | **1 门** | 逸剑 4 门是「平铺属性」的加法，傀儡升级槽稀缺，4 门会变成纯数值堆叠；1 门才有「流派身份」 | 少了组合自由度；P5 用「副心法（30% 被动、无阈值）」补 |
| 招式怎么限 | **按档位唯一**（二式/三式/绝式各 1 个），不做「N 个槽位」 | 逸剑就是每栏 1 个；档位天然对应资源台阶，工作台校验也简单（查 tag 即可） | 同档位想换招必须拆装（可接受） |
| 招式占不占升级槽 | **不占**（照特技先例） | 特技已经确立「武学类不占槽」；占槽会让「心法 3 份 + 3 招」吃掉 6 个槽，直接不可用 | 强度靠真气/CD/合成成本平衡；P5 若超模再加「武学槽」 |
| 境界怎么升 | **同件装 3 份 = L1/L2/L3** | 本家会把同名升级的等级累加（`GolemCommandModifier` 注释已确认「装三个 I 级就是 3 级」）；不引入新 UI | 要合 3 份玉简，前期成本高 |
| 集气条 | **不做** | 与攻击间隔重复 | 少了一个「行动序」博弈点 |
| 侧背击 | **不做** | 傀儡不绕后 | 少了一个空间维度 |
| 禁招五类 | **只做接口**，主力改「破绽」 | 原版怪没有招式/心法，破招/内伤对它们没意义 | PvP/傀儡内战时才完整 |
| 绝学（特技） | **本轮不动** | 用户定调「先不处理，只是看一眼」 | 短期两套主动技并存（特技 + 招式），P5 再统一 |

## 4. 真气

### 4.1 数值

| 项 | 值 | 说明 |
|---|---|---|
| 基础上限 | **60**（属性 `neili_max` 默认值） | 无属性加成时的裸上限 |
| 心法加成 | +5 ~ +65（按心法与境界，§5.2） | 加在属性上（`ADDITION`） |
| 修为加成 | +0 / +10 / +20 / +30 | 修为 100/250/450 三档 |
| 出生初始值 | 上限的 **50%** | 让开局第一发二式不用等太久 |
| 战斗回复 | **0.10 / tick**（2/s）× 心法倍率 | 有目标时才有 |
| 命中回复 | **+3** | 近战命中（含招式命中的本体，不含破绽追加段） |
| 受击回复 | **+2** | × 玄阴倍率 |
| 击杀回复 | **+8** | |
| 架势转化 | 每消耗 1 层架势 **+10** | 联动现有架势（§9） |
| 调息回复 | **1.0 / tick**（20/s）× 心法倍率 | 无目标 60 tick 后开始 |
| 走火扣血 | 缺口 × **2.0** | 只对允许走火的心法（血魔） |

节奏验算：假设 1 击/秒、心法 L1（上限 80）、二式 14 耗 → 命中 5/s 回气，约 **3 秒**一发二式；三式 30 耗约 6 秒；绝式 62 耗约 12 秒，正好被 240 tick（12 秒）CD 卡住。**CD 是主闸，真气是副闸**，两者不会互相空转。

| 事件 | 真气 | 备注 |
|---|---|---|
| 普攻命中 | +3 | 三连击的 3 段各算一次 → 三连击是「攒气机」 |
| 招式命中 | +3（只算本体那一下） | 追加段/破绽段不再回气 |
| 被击 | +2 | 有 0.5 秒内置 CD，防止高频小伤害刷气 |
| 击杀 | +8 | |
| 消耗架势 | +10 / 层 | 近战消耗架势时顺带回气 |
| 二式 | −12 ~ −20 | |
| 三式 | −25 ~ −35 | |
| 绝式 | −55 ~ −70 | |
| 调息 | +1.0/tick | 见 §4.4 |

### 4.3 三个阈值（借逸剑的「真气% 开关」）

| 状态 | 条件 | 通用效果 | 心法可改写 |
|---|---|---|---|
| **守势** | < 30% | 受伤 −5%、回气 +10% | 玄阴减伤更高、纯阳加护甲、归元回气更多 |
| **常势** | 30% ~ 70% | 无 | — |
| **攻势** | ≥ 70% | 招式伤害 +5%、招式耗气 −5% | 紫霞加攻速、血魔加吸血、太虚加剑意 |

> 阈值状态每 tick 维护一次：进状态挂属性修饰符，出状态摘掉（照 `GolemComboHandler.maintainSpeedPenalty` 的幂等写法）。**不要**在 `onHurtTarget` 里临时判断，否则读档后状态会漂移。
> 心法给的同名数值**替换**通用值（取较高者，不叠加），否则两套减伤会白送一截。

### 4.4 调息

- 触发：`getTarget() == null` 持续 **60 tick**（3 秒）。
- 效果：真气 +1.0/tick；每 20 tick 清 1 层内伤；粒子表现（脚下扩散的白色气环）。
- 打断：一旦有目标，立刻停止（不保留「调息中」状态）。
- 为什么不做成主动动作：傀儡没有「选择调息」的 AI，硬造一个只会在战斗中误触发；「无目标」这个条件已经足够精确。

### 4.5 走火入魔

只有**血魔大法**允许：

- 当 `真气 < 消耗` 但 `真气 ≥ 消耗 × 0.5` 时，仍可出招；
- 扣血 = 缺口 × 2.0（**不会致死**，最低留 1 点血）；
- 获得「内伤」100 tick：期间**不再获得任何真气**（命中/受击/击杀/调息全部停），并显示红色粒子。

这是「高风险高回报」的唯一入口，也是血魔的流派标识。其他心法在气不够时直接跳过该招式（AI 回落到普攻/低档招式）。

### 4.6 属性化（三个新属性）

照 `END_RESTITUTION` 的思路：**所有来源统一收进属性，再在读取处夹上限**。

| 属性 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `golems_arsenal:neili_max` | 60 | 0 ~ 10000 | 真气上限（心法/修为/材质/数据包都往这里加） |
| `golems_arsenal:neili_regen` | 1.0 | 0 ~ 10 | 战斗/调息回复的**倍率**（`MULTIPLY_TOTAL` 语义，读取时乘） |
| `golems_arsenal:move_power` | 0.0 | 0 ~ 10 | 招式伤害加成（0.15 = +15%），破绽**不吃**这一项 |

注册方式照 `ModAttributes.modifyAttributes`：挂到 `metal_golem` / `humanoid_golem` / `dog_golem` 三种实体上，`setSyncable(true)`。

> 为什么不把「当前真气」也做成属性：属性是「面板值」，会被其他 mod 的百分比修改器搅乱；当前值是一条会每 tick 变的资源，放 NBT 更稳（架势也是这么做的）。

### 5.3 境界与解锁

| 境界 | 达成 | 解锁 | 额外 |
|---|---|---|---|
| **L1 小成** | 装 1 份 | **二式** | 上限 +（表值 L1） |

- 境界只认升级件（`GolemUpgradeLevels` 的规矩），材质/数据包给的同名 modifier 不算。

### 5.4 修为（越用越强）

- 每只傀儡、每门心法各存一份 `ga_martial_prof_<art>`，0 ~ 450。
- 获取：命中 +1、击杀 +8、调息每 tick +0.05、放绝式 +3。
- 里程碑：**100 / 250 / 450** → 上限 +10/+20/+30，招式伤害 +2%/4%/6%（挂 `move_power`）。
- 跨里程碑时给主人发一条 action bar（「纯阳无极功 修为小成」）+ 一圈金色粒子。
- 拆掉心法**不清零**（换回来还能接着练）；换门派则各自独立。

> 为什么不用「熟练度百分比」而用绝对点数：绝对点数可以直接对标 `MYSTIC_UNLOCK_USES = 50` 的先例，也方便 `/ga martial` 调试时直接写值。

| 物品 | 配方（工作台） | 说明 |
|---|---|---|
| 心法·玉简（每门一个） | 纸 ×4 + 墨囊 ×1 + 金锭 ×1 + **门派材料** ×1 | 门派材料：纯阳=烈焰粉、玄阴=冰、紫霞=紫水晶、金刚=铁块、归元=绿宝石、混元=石英、血魔=腐肉、太虚=青金石 |

### 6.3 破绽与连招

- **破绽**：敌人身上的层数（0~5，8 秒，每次叠加刷新时长）。
- 增伤：**不走乘区**，每层折算成一段独立追加伤害（等效 +12% 攻击力/层）；只有「招式」能叠/吃，普攻/特技不参与。
- 结算方式：**独立追加段**（伤害类型 `move_break`），在招式本体命中后 1 tick 打出，
  数值 = `攻击力 × 0.12 × 层数`，不乘 `move_power`/暴击/磨砺 —— 防止和现有乘区双重叠乘。
- 消耗：绝式命中时吃掉全部层数，追加段改用 `0.12 × 1.5 × 层数`（「吃破绽」的 1.5 倍率），然后清空。
- 设计意图：二式/三式负责「铺」，绝式负责「收」，这就是傀儡版的连招 —— 不需要序列输入，只需要三个档位各装一个对的招。

### 6.4 同招递减（自创，参考侠客「切套路全 CD」+ 河洛「拙系」）

- 8 秒内重复同一个招式：第 2 次 −10%，第 3 次 −20%，第 4 次起 −30%（封顶）。
- 换一个招式立刻清零。
- 目的：让「三招轮转」优于「一招刷」，同时不引入「切套路全 CD」那种硬惩罚。
- 实现：每只傀儡存 `ga_martial_last_move`（id）+ `ga_martial_repeat`（次数）+ 时间戳。

### 6.5 出手决策（AI）

近战招式挂在 `onHurtTarget`（和特技同一时机），远程招式挂在投射物命中/发射（和架势弓同一时机）。**每次普攻最多触发一个招式**，保证节奏不被连发打乱。

```text
onHurtTarget(golem, event):
    if 客户端 or 事件来自自己的追加伤害: return
    if 目标已死 or 是友军: return
    if 内伤中: return
    真气 += 3
    破绽/同招记录维护
    for move in [绝式, 三式, 二式]:            # 高打低
        if not installed(move): continue
        if 境界 < move.tier: continue
        if now < cooldown(move): continue
        if 真气 < move.cost and not (血魔 and 真气 >= cost/2): continue
        cast(move); break
```

- 冷却按招式 id 各存一份（`ga_martial_cd_<id>`），**不复用** `specialAttackCoolDown`（那是本家的字段，特技在用）。
- 绝式的额外条件：`破绽 ≥ 2` 或目标血量 > 50%（避免对着残血小怪交大）。
- 远程招式：`isInRangedMode()` 且目标距离 4~16 格；近战招式：`!isInRangedMode()`。

### 6.6 硬直与攻速仲裁

- 出招后 N tick 内，把**攻击间隔**拉长：目标攻速 = `20 / (20 + 硬直)`（二式 0.833、三式 0.714、绝式 0.625）。
- 必须走「绝对值压制」：本家公式是 `ceil(20 / min(1, 攻速))`，**攻速 ≥ 1.0 时免疫**（三连击注释里踩过）。
- **与三连击冲突**：`GolemComboHandler` 每 tick 会把攻速硬压到 0.6，会覆盖硬直。
  → P2 必须抽一个 `GolemAttackSpeedArbiter`：收集「三连击基准 0.6」「硬直目标值」两个意图，取**更慢**的那个，每 tick 只写一次。**不要**让两个 handler 各写各的。

### 6.7 与特技（绝学）的边界

| | 招式 | 特技（绝学） |
|---|---|---|
| 数量 | 每档 1 个，最多 3 个 | 互斥，最多 1 个 |
| 消耗 | 真气 | 无 |
| CD | 30 ~ 260 tick | 80 ~ 160 tick（硬编码） |
| 触发 | 普攻命中时按优先级 | 各自的 handler（键刃/凤凰/冲撞…） |
| 本轮 | 新建 | **不动** |

两套并存的风险：同一个 `onHurtTarget` 上，特技和招式可能同一次攻击都触发（伤害叠加）。P2 验收时要测「狮子斩 + 绝式同回合」的实际爆发，必要时给特技加一条「本 tick 已出招则跳过」。

## 7. 状态与克制

### 7.1 敌人侧：破绽（v1 唯一要做的敌方状态）

- 存储：目标实体的 `persistentData`（`ga_break_stacks` / `ga_break_until`）。
- 表现：目标头顶/身上冒橙色小粒子（每 10 tick 一次，层数越多越密）。
- 兼容：任何 LivingEntity 都能叠，包括其他 mod 的 Boss；死亡/换维度自然失效。
- 伤害类型 `golems_arsenal:move_break` 的标签取舍：
  - 进 `bypasses_armor` + `bypasses_cooldown`（照 `stance_magic`），保证追加段一定落地；
  - **不进** `is_magic`：灾变/试炼傀儡的 `modulargolems:magic_immune` 会取消 `forge:is_magic` 的伤害（TRIAL-MECHANICS 已实测），破绽段要是进了这个 tag，对精英直接归零 —— 这是设计选择，不是遗漏。

### 7.2 自己侧：内伤 / 硬直 / 走火

| 状态 | 来源 | 效果 | 时长 |
|---|---|---|---|
| 内伤 | 走火入魔 | 不获得任何真气 | 100 tick |
| 硬直 | 出招 | 攻速绝对值下降（§6.6） | 二式 4 / 三式 8 / 绝式 12 tick |
| 走火 | 血魔 + 气不足 | 扣血 + 内伤 | 即时 |

### 7.3 逸剑的五种禁招：只留接口

破招/内伤/断筋/气绝/封穴 只有在「对方也有招式/心法/轻功」时才有意义。原版怪没有，所以 v1 不做主动施加，只留：

```java
public interface MartialStatus {
    void applyBreakAction(golem, ticks);   // 破招：禁招式
    void applyInnerInjury(golem, ticks);   // 内伤：禁回气（已有）
    void applyTendonCut(golem, ticks);     // 断筋：减速
    void applyQiDepletion(golem);          // 气绝：清零
    void applySeal(golem, ticks);          // 封穴：三者叠加
}
```

- 未来由「会武学的敌人」（傀儡内战的敌方傀儡、玩家 PvP、其他 mod 的武者）调用。
- 为什么不现在做：做了也没有施加者，等于 5 个死代码 + 5 个新 MobEffect 贴图。

### 7.4 六属性相性（可选，P5，默认关）

- 借太吾的六属性：金刚/玄阴/紫霞/纯阳/归元/混元。
- 招式带属性，目标按实体类型 tag 映射（亡灵=玄阴、节肢=金刚、灾变=纯阳、水生=归元…）。
- 同属性 +20%，被克 −10%，混元恒 +5%。
- **必须数据包驱动**（`data/golems_arsenal/martial_affinity/entity_type_tags/*.json`），默认 `martial_affinity_enabled = false`，因为它会和其他 mod 的怪物分类打架。

## 8. 成长与经济

### 8.1 三条成长轴

| 轴 | 载体 | 上限 | 获取 | 影响 |
|---|---|---|---|---|
| **境界** | 心法物品份数 | L3 | 合成 3 份 | 上限 + 档位解锁 |
| **修为** | 每傀儡每心法 NBT | 450 | 战斗/调息 | 上限 +30、招式伤害 +6% |
| **精修** | 每傀儡每招式 NBT | 250 次 | 使用该招式 | 伤害 +20%、CD −10% |

- 精修曲线：每 25 次 +2% 伤害（250 次封顶 +20%）；每 50 次 −2% CD（250 次封顶 −10%）。
- 所有成长都**只加在 `move_power` / 上限 / CD 上**，不引入新的乘区（乘区已经够多了：破绽、心法相性、阈值、暴击、磨砺、炎拳）。
- 满配理论值：`1.0（基础）× 1.2（精修）× 1.06（修为）× 1.20（心法绝式）× 1.05（攻势）× 1.15（相性）≈ 1.85×`，再加破绽独立段 —— 这是有意留的天花板，P3 实测后再调。

### 8.2 物品与配方

- **26 件新物品**：8 心法玉简 + 18 招式残页。
- 物品/模型/配方全走现有约定：
  - item id：`art_<name>_upgrade` / `move_<weapon>_<name>_upgrade`；
  - modifier id：去掉 `_upgrade`（本仓库的命名规则）；
  - 模型：`assets/golems_arsenal/models/item/<id>.json`，`layer0` 复用两张共享贴图（`manual` / `page`），**只换 tint 或直接共用**，不再画 26 张图；
  - 配方：`data/golems_arsenal/recipes/<id>.json`，26 个手写太蠢 → 写一个 `tools/gen_martial_jsons.py` 批量生成（仓库里已有 python 工具的惯例）。
- 创造模式页：26 件会把现有 41 件冲散 → 在 `ModItems.TAB` 里按「心法 / 二式 / 三式 / 绝式」四段插入，或新开一个 `武学` 子页（P2 决定）。

| 类别 | 占升级槽 | 互斥规则 | 校验位置 |

### 10.4 mixin 改动（唯一一处）

`GolemUpgradeHandlerMixin$golemsArsenal$rejectSecondSpecialMove` 里，在合金链检查之后、特技检查之前插入：

```java
String rejection = MartialSlots.rejection(upgrades, incoming, golem);
if (rejection != null) {
    cir.setReturnValue(ItemStack.EMPTY);
    return;
}
```

`MartialSlots` 做三件事：

1. 心法：`upgrades` 里已有**别门**心法 → 拒绝（同门允许叠到 3 份，由 maxLevel 兜底）；
2. 招式：同档位已有别的招式，或**同一招重复装** → 拒绝；
3. 招式：从 `GolemHolder.getUpgrades(golem)` 算心法境界（需要给 `GolemUpgradeLevels` 加一个 `Iterable<IUpgradeItem>` 重载），低于档位要求 → 拒绝。

> 这个 mixin 注入的是 **mod 自己的类**（`GolemUpgradeItemHandler`），不需要 refmap 条目；只有注入 vanilla 方法才需要手工维护 `golems_arsenal.refmap.json`（文件头注释已写明）。

- `/ga martial`：打印准星所指傀儡的心法/境界/真气/修为/已装招式/冷却。
- `/ga martial neili <值>` / `/ga martial prof <值>`：直接写，方便测阈值与里程碑。
- 验收脚本（手动）：
  1. 空手傀儡装纯阳 L1 → 上限 80（出生时当前值 = 上限的 50%）；
  2. 脱战 3 秒 → 回气开始，2 秒回满（L1 上限 80）；
  3. 装白虹 → 每秒一记普攻，约 3 秒出一次；

## 11. 风险与坑（本仓库特有）

| # | 坑 | 表现 | 处理 |
|---|---|---|---|
| 1 | `invulnerableTime` | 多段招式只有第一段生效 | 每段前 `target.invulnerableTime = 0`（照 `GolemComboHandler.hitArc`） |
| 2 | `schedulePersistent` 单跳 | 追加段每 tick 打一次，伤害数字停不下来 | 加 `boolean[] fired` 硬护栏（照 `GolemCommandModifier.scheduleExtraHit`） |
| 3 | 攻速公式免疫 | 硬直写了但间隔不变 | 必须压到 **< 1.0** 的绝对值；`ceil(20 / min(1, 攻速))` |
| 4 | 攻速多来源互踩 | 三连击把硬直覆盖，或反之 | 抽 `GolemAttackSpeedArbiter`，每 tick 只写一次 |
| 5 | 属性修饰符残留 | 拆心法后护甲/上限不还原 | 每 tick 幂等维护（先比对再增删），UUID 固定且按「心法+属性」区分 |

## 12. 待拍板（写代码前需要定的 8 条）

1. **心法占不占升级槽？** 本文默认不占（照特技先例）。占槽更平衡，但「3 份圆满」会吃掉 3 个槽。
2. **境界用「3 份同名」还是「1 份 + 修为自动升」？** 本文默认 3 份（本家等级累加，零新 UI）；自动升更省物品，但要自己做等级 UI/提示。
3. **走火入魔要不要？** 它会真的把傀儡打死（留 1 血）。血魔没有它就是纯白板。
4. **招式吃不吃普攻管线？** 本文默认吃（附魔/磨砺/炎拳/莫厄全触发）。吃 = 和现有系统自然联动，但伤害会被现有乘区放大；不吃 = 干净但要另写一套结算。
5. **破绽段进不进 `is_magic`？** 本文默认不进（对 magic_immune 有效）。进了更「魔法」，但对试炼精英无效。
6. **18 个招式一次做完，还是先做剑 3 档？** 本文建议先剑 3 档跑通再铺量。
7. **要不要「副心法」？** 太吾的周天栏位；P5 可选，给 30% 被动、不给阈值。
8. **要不要 JEI / Patchouli 说明页？** 26 件新物品没有说明页，玩家只能靠 tooltip。
