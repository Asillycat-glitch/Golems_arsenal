## 3. 本轮改了什么

### 3.1 新增：硬锁层

| 文件 | 作用 |
|---|---|
| `guard/sanctuary/Aegis` | 每 tick 强制不变量：`guardedData >= 账本`、`DATA_HEALTH >= 账本`、`removalReason==null`、`dead/deathTime` 清零、装备槽补回；并触发 `GungnirRecovery` |
| `guard/sanctuary/GungnirRecovery` | 反射清 toaru 的 `TerminalAuthority.release` / `GungnirLedger.forget` / `toaru_birth_origin_v1` |
| `guard/sanctuary/GolemKit` | 装备槽快照；只在"最近 200 tick 被篡改过"时补回被清空的槽 |

### 3.2 判据改成"账本"（不再看 raw）

- `Sanctuary.preventDeath`：`expected > 1` 就否决 `die`（原来要求 `raw > 1`——攻击方同一 tick 写 0 再 die 就绕过）。
- `Sanctuary.onLivingDeath`：阈值从 `max*20%` 改成"账本 > 1"。
- `Sanctuary.blockExternalClear`：条件是 `Aegis.alive(golem)`（账本口径）。
- `LivingEntityAliveReadMixin` / `GuardedEntityHealthReadMixin`：读侧按 `max(raw, 账本)` 回答。
- `RemovalGuard.hardRepair`：硬锁无条件清 `removalReason`（原先要满足最近篡改 + 20% 阈值）。
- `RemovalGuard.hardRepair` 对 `UNLOADED_*` 不再一律放行：区块还开着就当冒充卸载（fantasy `DeleteCommand`）。

### 3.3 新增 mixin

| mixin | 目标 | 作用 |
|---|---|---|
| `ArcaneVortexKillerGuardMixin` | `EntityKillerHelp.*` | killEntity/kill/tickDeath/AsynchronousRemove/setRemoved/remove/deleteEntity/removeServerLevelEntity/setEntityPos* |
| `ArcaneVortexHealthModifyGuardMixin` | `HealthModify.entityDataModify/traversalModify` | 拦"按值匹配再 putfield"的血量直写 |
| `GungnirAuthorityGuardMixin` | `GungnirDamageApi$Authority#isProtected` | 恒 true → 全链短路 |
| `GungnirLedgerGuardMixin` | `GungnirLedger#shouldBlock/record` | 一票否决 Reaper/索引/重入 |
| `GungnirExecutionGuardMixin` | 追加 `finishRemoval` | 拦移除三连 |
| `DropLootGuardMixin` | `LivingEntity#dropAllDeathLoot` | 活着的傀儡不掉战利品 |
| `EntityLevelCallbackGuardMixin` | `Entity#setLevelCallback` | 拒把傀儡换成 NULL callback（"不会动的雕像"） |

`golems_arsenal.mixins.json` / `golems_arsenal.refmap.json` 已同步；新增的 refmap 条目只有两条
（`dropAllDeathLoot -> m_6668_`、`setLevelCallback -> m_141960_`），其余 mixin 目标都是 mod 自己的类（`remap=false`），不需要 refmap。

## 4. 关键机制备忘（下次别踩）

- **账本只在被准入的伤害事件里下降**（`HealthLedger.onDamage`），治疗/上限提升一律承认向上变化。
  这就是"同 tick 写 0 + die/remove"拦得住的原因。
- **`GuardedEntity.getHealth()` = `max(super.getHealth(), guardedData)`**，所以修 `guardedData` 比修 raw 更根本；
  `setGuardedDataImpl(v, true, false)` 是唯一"强制"写法（`force=true` 才不会被动减保护压住）。
- **账本只管下界**：`HealthLedger.audit` 不再无条件采纳 raw（否则攻击方在审计那一 tick 写 0，账本就把 0 当应得值）。
  硬锁回写带 `max(1.0, 1% 上限)` 容差，避免把伤害事件的取整误差变成隐式回血。
- **`setHealth` 在 `GuardedEntity` 里是 final 的 `m_21153_`**，且 `tickCount > 5` 之后**拒绝任何下降**
  （`GuardedEntity:136`）——所以攻击方基本无法用 `setHealth` 打死傀儡，真正的击杀都走 D2/D3。
- **升级件只在 `AbstractGolemEntity.upgrades`**，只在 `GolemHolder.setEntity` 时写进物品；
  `dropGolemLoot` 不掉升级。→ 实体被 `setRemoved`/`remove`/`discard` 移除（且 hp>0）时升级直接消失。
  `the_risen` 只是 `RECYCLE|REVIVE` 两个 flag，不保护升级。
- **`modulargolems` 自己的 mixin 会把 `setRemoved` 路由到 `onRemove → untrackRemoved`**，
  所以"拦 `setRemoved`"同时也保住了回收/升级链。
- **toaru 的 `shouldBlock` 是一切事后追杀的根**；账本一写进去，Reaper 每 5 tick 再来一次。
- **fantasy 的 `DeleteCommand` 用 `UNLOADED_TO_CHUNK` 冒充卸载**（`shouldDestroy=false`），
  不进 `onRemove`、不触发回收；判据是"区块还开着"。
- **AV 的 `VanillaBypass`** 把 `hurt/die/dropAllDeathLoot/spawnAtLocation` 转发到原始字节码副本，
  所以对 AV 的守卫必须放在**它自己的类**上；原版方法上的 mixin 会被绕开。

## 5. 为什么没有启用 agent

`sanctuary-agent` 的补丁列表（HardErase / NativeAgentHealthMethod / GungnirExecution /
GungnirArcaneCompat）现在已经被 mod 层 mixin + Aegis 覆盖；agent 在 2026-11-07 崩过两次
（类加载器 + 半清除实体），在没有重新验证之前保持 `agent_enabled=false`。
如果以后要开：先只开 `verbose=true` 跑一轮，确认没有 `transform failed` 再放行。
