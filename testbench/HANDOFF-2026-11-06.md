## 2. 当前运行配置

`config/golems_arsenal-common.toml`：

```toml
[damage_admission]
default_deny = true
strict_writes = true
window_enforce = true
combat_mode = "SHADOW"   # 可能被运行时改成 ENFORCE，重启后回 SHADOW
combat_radius = 16

handled_mods = ["fantasy_ending"]
handled_damage_types = ["fantasy_ending.fe_power", "fantasy_ending.ds_power"]
handled_items = ["fantasy_ending:fantasy_ending_sword"]

[sanctuary]              # 2026-11-06 新增
mode = "SHADOW"
deny_owner = true
deny_ally = true
deny_unattributed = true
allow_environment = true
allow_generic_kill = false
deny_operation = true
removal_guard = "SHADOW"

[compat]
fantasy_true_health_sync = true
```

注意：

- `combat_mode=SHADOW` 只记录，不取消；`/ga guard combat enforce` 才取消。
- `[sanctuary] mode` 现在才是主判定；`combat_mode` 只剩左键/命中的物品画像日志。
- `sanctuary.allow_generic_kill=false` 意味着受保护傀儡对 `/kill` 免疫（这是有意的）。
- `fantasy_true_health_sync=true` 仍可能把 `guardedData` 向下同步到 raw，和 split-brain 有冲突；见未决项。
- `handled_*` 仍是 **mod/item id 名单**；它现在只影响 true-damage 归一化，不再决定“谁可以打傀儡”。

## 3. 最近已验证的结果

### 3.1 梦终 true damage 已落地

最新日志：

```text
[DamageAdmission] handled ... source=fantasy_ending.fe_power.*
  iframeReset=20->0 applied=true postHealth=...
[DamageAdmission] fantasy_attack stage=highest/high/normal/low/lowest
  canceled=false
```

- `applied=true` 出现；
- `applied=false` 消失；
- `fantasy_attack` 各阶段全部 `canceled=false`；
- `iframeReset` 生效；
- `fantasy_hurt` 也出现。

结论：**true damage 的 rehurt 已经能实际掉血**，不再是“cancel 后归零”。

### 3.2 但死亡路径仍有问题

日志仍有：

```text
[DamageAdmission] rejected data.health amount=0.0 raw=100.0
[GuardAudit] UNEXPLAINED_HEALTH expected=0.0 raw=100.0 actual=0.0 delta=100.0
```

用户明确：**梦终死亡特殊处理交给 fantasy 自己，应该放行**。

当前没有实现“death-path allowance”，所以 `setHealth(0)`/`data.health=0` 仍可能被 default-deny 拦，导致：

- 死亡事件/掉落/移除不完整；
- raw/guarded 再次分裂；
- audit 反复。

方向：只放行 **死亡路径**（`LivingEntity.die` / `GuardedEntity.die` / 死亡栈），不要放行“任意时刻 setHealth(0)”。

### 3.3 ArcaneVortex（秘法涡流）

- `CombatProfiles` 目前对 `com.erchien.arcanevortex.` 的非方块物品统一加 `CUSTOM_HOOK`；
- `CombatAdmission` 在 SHADOW 下会记录：

```text
[CombatAdmission] would_reject inventory_tick
  item=item.arcanevortex.van_sh
  caps=[CUSTOM_HOOK, NORMAL_MELEE]
```

- 没有取消（SHADOW）；
- 用户真正想防的是：**不小心手持元式左键点到自己的傀儡**；
- 用户明确不想要“右键范围整段被吞掉，看起来像模组冲突”；
- 因此后续应改成 **attack-only**（只保留 `AttackEntityEvent` + `LivingAttackEvent` 的 target 判断），不要再用 `RightClickItem` / `UseItem.Start` / `inventoryTick` 整段取消。

### 3.4 Dragon Golem / 倒地可回收

用户截图：龙傀儡周围右键导致崩溃；随后说明“这个状态可回收，甚至不需要手杖”。

日志：

```text
[GuardAudit] REMOVED_WITHOUT_DEATH
  uuid=12de59b8-...
  reason=DISCARDED raw=664.7816 / 665.1781
```

关键：

- 这是 `DISCARDED`，不是 `KILLED`；
- HUD 心形空、模型倒地是 Dragon Golems 自己的状态；
- **removal guard 必须放行 `DISCARDED` / `UNLOADED_TO_CHUNK`**，只拦 `KILLED` 且还活着的移除；
- 当前没有 removal guard，所以它只是 audit 误报，不阻止回收。

### 3.5 崩溃：ArcaneVortex 的 NPE（已确认不是我们的）

崩溃：

```text
EntityKillerHelp.kill(EntityKillerHelp.java:132)
  -> Objects.requireNonNull(entity.getDeathSound())
```

根因：

- VanSh 的 `releaseUsing`（`m_5551_`）调用 `EntityKillerHelp.kill`；
- 龙傀儡 `getDeathSound() == null`；
- ArcaneVortex 没判空。

用户明确：**交给 Dragon Golems / ArcaneVortex 修**。

曾加过 `LivingEntityDeathSoundFallbackMixin`，随后按用户要求 **已完全回退**：

- 源码删除；
- `golems_arsenal.mixins.json` / `refmap.json` 移除；
- jar 内无 `DeathSoundFallback`。

**不要再加这个 fallback。**

## 4. 当前代码地图（重要文件）

### 4.1 健康 / true damage

- `compat/artifact/DamageAdmission.java`
  - `strict_writes`：non-finite / off-thread；
  - `default_deny`：直写下降拒绝；
  - `normalSource`：`golems_arsenal:admission_rehurt`，无 attacker；
  - `isHandled`：`handled_mods` / `handled_damage_types` / `handled_items`；
  - 目前没有 death-path allowance。
- `compat/fantasy/FantasyTrueDamageAdapter.java`
  - 只注册 `CatchActuallyHurt0Event.Pre`，**不要加回 PrePre**（会双重 cancel/re-hurt）；
  - rehurt 前临时 `invulnerableTime=0`，失败恢复；
  - 诊断：`fantasy_pre`、`fantasy_attack` 五个优先级、`fantasy_hurt`；
  - `handled=false` 仍 `rejected true_damage`。
- `compat/fantasy/FantasyTrueHealthCompat.java`
  - 当 raw >0 且低于 guarded，5 tick 后把 guarded 向下同步到 raw；
  - 对 `raw=0.1 / guarded=558` 这种 split-brain 有风险；
  - 当前配置 true，但最近日志没有 `[Compat]` 行，仍需注意。
- `guard/HealthLedger.java`
  - 只审计，不 reconcile；
  - `UNEXPLAINED_HEALTH` 正向/负向都可能；
  - `REMOVED_WITHOUT_DEATH` 对 `DISCARDED` 会误报。

### 4.2 Combat / ArcaneVortex

- `guard/combat/CombatCapability.java`
  - `NORMAL_MELEE`, `NORMAL_RANGED`, `CUSTOM_HOOK`, `CONTINUOUS_HOOK`, `GLOBAL_EVENT_HOOK`, `PROJECTILE_OR_SPELL`。
- `CombatProfiles.java`
  - 原版剑/工具/三叉戟/弓/弩；
  - 纯远程兼容：`pureRanged` 不加 CUSTOM；
  - **ArcaneVortex 非方块物品**用 `com.erchien.arcanevortex.` 前缀加 `CUSTOM_HOOK`；
  - 这种 namespace 判断是“指名 mod 类”，用户已知，后续可换成 capability adapter。
- `CombatAction.java` / `ItemProfile.java` / `CombatAdapters.java`
  - `CombatAction` 聚合 contributor；
  - `CombatAdapters` 目前没有具体 adapter；
  - `ItemProfile.supported` 与 `CombatAction.supported` 是两套逻辑（无 adapter 时一致）。
- `CombatAdmission.java`
  - `SHADOW` / `ENFORCE` / `OFF`；
  - 当前仍会取消 `RightClickItem` / `UseItem.Start` / `inventoryTick` / `swing`（在 ENFORCE 下）；
  - 这正是用户不想要的“整段 use 被吞”；
  - 方向：attack-only。
- Mixins：
  - `ItemStackCombatAdmissionMixin`（`inventoryTick`）
  - `LivingEntitySwingCombatAdmissionMixin`（`swing`）
  - 这两个是否保留取决于 attack-only 决策。

### 4.3 Golemmagicka（已修）

- `mixin/golemmagicka/GolemSpellManagerMixin.java`
- `mixin/golemmagicka/SpellCategoryUtilMixin.java`

之前崩溃：


**不要改回直接引用。**

> [SANCTUARY-2026-11-06.md](SANCTUARY-2026-11-06.md)。下面保留原始决策记录，作为“当时为什么这么做”的上下文。

### A. 立即（低风险）——已实现

1. **attack-only 收窄**：`CombatAdmission` 现在只剩 `AttackEntityEvent` + `LivingAttackEvent`；
   use / useOn / interact / use_start / inventory_tick / swing 的取消全部删除，两个对应 mixin 已删文件。
2. **death-path allowance**：不再按调用栈，改成 `SanctuaryScopes` 的 death/load/internal 作用域 +
   `hurt` 窗口；`GuardedEntity#die` 单独包了一层（它的 die 可能不走到 vanilla die）。
3. **removal guard**：`Entity#setRemoved` mixin + `RemovalGuard`，按 `RemovalReason` 判；
   `DISCARDED` / 卸载 / 跨维度放行，只有“活体 KILLED”会被拦（默认 SHADOW）。

### B. 大胆路线——已实现

**Golem Sanctuary** 已落地（`guard/sanctuary/*`）：

```text
owner / owner projectile / 同主傀儡 -> 拒绝
敌人 / 环境 -> 放行正常 hurt
golems_arsenal 命名空间的伤害类型 -> 放行（即 L2 内部标记，不需要新 tag）
```

- `generic_kill`（`kill()` / `/kill`）默认算“说不清来路”，会被拒；
  `sanctuary.allow_generic_kill=true` 可放行。
- 代价与空洞（宿主模组包内写、`forceHurt`/`forceRemove`、`kill()` 的 dynamic-reduction 分支）
  都写在 SANCTUARY 文档第 7 节。

### C. 暂缓

- `true_damage_mode=preserve/block/audit`：等这轮 Sanctuary 进游戏验完再说。
- 自动 reconcile raw/guarded：用户目前接受“回收/放出修复”，不做自动写血。
- 死亡音效 fallback：已回退，不要加回。

## 7. 不要再做

- 不要再加 death sound fallback；
- 不要把 `PrePre` 注册回 `FantasyTrueDamageAdapter`（会双重 re-hurt）；
- 不要再加 tag 文件；
- 不要按 item id 继续扩黑名单；
- 不要把“无 attacker”当成“一定落地”；
- 不要在没有 L2 adapter 的情况下假设 L2 会处理无 attacker 伤害；
- 不要把 `DISCARDED` 当成恶意移除。
